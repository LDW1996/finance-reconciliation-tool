# 邮件并发专项检查

范围：邮件导入、附件识别、付款摘要写入、队列确认、配置启停、存储维护和数据库连接释放。仅本地测试，不操作真实邮箱或解锁平台。

## 本次修复

- 附件内容更新时，旧识别任务必须校验原件摘要，不能将旧结果写入新原件；付款摘要保存也校验邮件和附件快照。
- 识别期间新增附件必须保留待处理队列，不能随旧任务完成而丢失。
- 保存配置启动读取时携带代次，过期请求不能在用户暂停后重新启动。
- 识别线程或维护线程启动失败、维护准备写入失败时，释放运行标记并保留故障信息。
- 导入保存与加入识别队列保持管理锁保护，避免清理在两步之间进入。
- 数据库连接关闭异常仍释放写入门闩，避免后续写入永久等待。

## 追加修复：配置与 OCR 隔离

- 自动读取配置独立存放在与邮件库同目录的加密 `.poll` 文件，使用原有密钥。首次从旧库迁移，此后以独立文件为准。原子替换写入，保存失败不应用新配置；备份应继续复制完整数据目录。
- 配置保存与后台启动分离，配置返回不等待邮件写入门闩或 Outlook。启停和自动恢复统一核对配置代次，旧请求不能覆盖后续暂停。
- 队列确认在数据库写事务中重新核对附件状态，避免为了保护确认窗口而在整批保存期间占住配置操作需要的锁。
- OCR 使用可回收的独立 spawn 进程；超时终止并等待退出，下一次尝试使用新进程，其他识别进程保留。
- 单附件默认超时 600 秒，环境变量 `FINANCE_OCR_TIMEOUT_SECONDS` 可设 30–3600 秒。保守上限用于兼容较长 PDF；超时最多自动重试一次，再失败保留原件和原因，继续其他附件。明确手动重试可重新申请尝试次数。
- 临时原件与结果仅用于进程传递，完成或确认终止后删除；无法终止的进程隔离并记录，不能丢弃句柄或悄悄当作成功。

## 尚存边界

- 配置文件写入仍依赖本机磁盘；磁盘、权限故障会明确报错，不能保证异常磁盘下即时成功。
- Python 写入门闩只协调同一进程，不协调多个应用进程；SQLite 自身仍处理跨进程竞争。应避免多个实例同时使用同一数据目录。
- 本地回归不能替代 Windows Outlook COM、原生 OCR 和 Windows 打包验证。

验证：完整后端回归 546 项通过、2 项跳过（39.25 秒），差异空白检查通过。包含真实 spawn 卡死终止、进程替换、手动重试、无法终止时隔离，以及数据库写入占用下的配置响应测试。

本次不自动打包、提交或推送。Windows 冻结成品仍需手工打包验证。
