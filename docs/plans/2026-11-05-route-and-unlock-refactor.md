# 路由与解锁流程结构整理

按已确认顺序实施，不改变 API、默认值、数据目录或执行策略。
1. 提取本机请求守卫与前端目录/静态资源托管，保留独立版差异与语言。
2. 将 iLog 路由、请求模型从 main 提取到 ilog_routes。
3. 将邮件接口分为存储、消息扫描、在线台账、客户映射、匹配导出、诊断；保留 mail_tasks.create_router 兼容入口和延迟 manager 获取。
4. 提取解锁复查、失败描述、结果整理等阶段，保留持久化提交意图和异常边界。
5. 比对拆分前后路由契约，运行相关现有测试；不操作真实订单、不打包、不提交推送。

## 实施结果
- 新增 web_common：守卫条件统一，保留入口语言与邮件独立版前端目录覆盖；统一限制前端路径不越界，未知 API 不回退 HTML。
- 新增 ilog_routes：保留账号 GET 在邮件接口之前的历史注册顺序，入口保留已有集成使用的类/模块兼容导出。
- 新增 mail_routes 及六个分组：48 个端点的函数语法树（仅限定模块引用）、路径、方法、状态码和顺序比对一致；manager 仍由 mail_tasks 延迟取得，没有复制单例。
- 解锁提取单笔提交返回、复查、失败描述、截图；批量提取选中、复查、结果整理。持久化提交意图和 finally 清理边界留在原流程。
- mail_tasks.create_router 320→4 行，main 297→61 行；run 280→190 行，execute_batch 130→92 行。未为了缩短行数移动核心异常边界。
- 相关现有测试及新增公共策略测试共 187 项通过；解锁阶段二次调整后 53 项重新通过。未运行全量测试、真实平台解锁、Windows 打包或发布。
