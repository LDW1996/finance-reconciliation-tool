# iLog 后续需求：航次解锁与提速

用户于2026-11-02补充；已实现航次预览、解锁及会话复用。2026-11-03按用户授权完成首批真实验证。

## 航次解锁

- 保留现有按提单解锁，增加按航次操作。
- 输入该航次的一票提单号，不要求用户手填船名、航次。
- 费用解锁（Vessel）：解开对应航次所有提单的小锁。
- 订单解锁（Vessel）：解开对应航次所有提单的大锁。
- 页面仍应清晰区分费用与订单输入位置、操作范围及结果。
- 一个号码可能查出多条记录，且可能分属不同航次。示例截图 SITSKBAR783892 返回两条记录；不能默认首条即为用户期望范围。开发时需确认记录各自船名/航次及平台批量菜单的实际作用范围，再确定选中策略。
- 同一账号、同一航次、同类解锁去重，避免多个代表提单重复提交同一航次。
- 日志记录输入提单、实际账号、命中业务、船名航次、操作类型、平台响应和复查结果；无法确认全航次范围时不能声称全航次均解锁。
- 首批5个代表提单合并为2个航次，费用/订单共4次航次操作均收到平台成功响应，代表单复查通过；平台未提供全航次影响数量，未声称逐笔核验全部提单。

## 提高解锁速度

- 分阶段计时：浏览器启动、登录、查询、选中、解锁提交、状态复查、截图、结果保存；先找出实际瓶颈。
- 优先评估同一任务复用浏览器及账号会话、减少重复导航与查询、以页面明确加载/响应信号代替不必要的固定等待。
- 评估成功默认只存结构化结果、异常保留截图；截图设置超时，避免拖住队列。截图策略实现前统一页面文案和保存设置。
- 保留状态复查；提交结果不明时先只读核查，不能为提速重复发送解锁。
- 单笔异常继续后续订单，保留财务可读原因。
- 优化前后用相同条件比较每单及整批耗时，不预先承诺提速百分比。
