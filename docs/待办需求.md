### 航次解锁（需求 2026-10-28，完成 2026-11-03）

原始需求：输入该航次任一提单，查询船名与航次，通过平台费用解锁(Vessel)、订单解锁(Vessel)执行整航次操作。普通提单解锁保留。

接入要求与落实位置：

| 要求 | 落实方式 |
| --- | --- |
| 清单显示船名/航次 | `POST /api/ilog/voyages/preview` 返回按账号+船名+航次+类型分组的结果，前端在核对清单中展示 |
| 同航次去重 | `ilog_voyage.build_groups` 以 SHA256(账号, 船名, 航次, 类型) 为键合并代表提单 |
| 不同航次或缺少船名航次不能默认取第一条 | 缺业务记录编号、船名、航次，或字段含 `/` 时直接拒绝，不做范围猜测 |
| 记录平台响应及复查范围 | 新增 `voyage_platform_confirmed` 状态，文案明确为「平台已确认航次操作成功（仅代表单）」 |

实现位置：

- `backend/app/ilog_voyage.py`——航次分组与范围校验
- `backend/app/ilog_tasks.py`——`voyage_previews` 预览令牌（10 分钟有效，绑定账号、兜底账号与输入单号；预览存在 issue 或无可执行分组时禁止提交）
- `backend/app/main.py`——`POST /api/ilog/voyages/preview`
- `frontend/src/views/UnlockView.vue`——按提单 / 按航次切换

验证：`backend/tests/test_ilog_voyage.py`、`test_ilog_voyage_api_integration.py`。首批 5 个代表提单合并为 2 个航次，费用/订单共 4 次航次操作均收到平台成功响应，代表单复查通过；平台未提供全航次影响数量，因此未声称逐笔核验全部提单。

技术说明见 `backend/ILOG_UNLOCK.md` 的「航次解锁」。
